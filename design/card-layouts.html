Card layout alternatives

Four ways to lay out the equipment cards, on the real design tokens and the real instrument list. Pick a direction; the winner gets ported into the Nunjucks partial. Every option keeps selection JavaScript-free — the checkbox is the control, the label is the clickable face.

Demo data. The live list currently has every instrument at status needed. A few rows below are shown as offered and secured so you can judge how each layout handles all three states. Try toggling the tick controls — no scripts run on selection, exactly as in production.

Option A — Datasheet grid

spec-forward

Specs on the face. Model examples, quantity and loan weeks sit in a labelled key/value block instead of hiding under a disclosure. Densest option; best when the reader's first question is "would my unit qualify?"

    Option B — Compact rows

    triage list

    One row per instrument. A status colour-bar on the left edge, name and a single meta line in the middle, tick on the right. Scans fastest down a long list and reads like a checklist you work through.

      Option C — Status-led tiles

      call to action

      Status up top, action at the foot. A bold coloured band carries the state; selecting is a full-width button. Leans persuasive rather than informational — useful if the goal is nudging lenders to claim an item.

        Option D — Checklist

        minimal

        Bone-simple. Tick, name, one quiet meta line, hairline dividers. Closest to today's cards in spirit, just flatter and tighter. Details still tuck into a disclosure so nothing usable is lost.
